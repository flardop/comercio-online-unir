# Reparto inicial para seis personas

Este reparto es una propuesta. Los nombres se pueden añadir cuando el equipo lo acuerde. Cada bloque tiene una persona responsable, pero todas las solicitudes de revisión deben ser revisadas por otra persona.

| Persona | Responsabilidad principal | Primeras tareas |
| --- | --- | --- |
| 1 | Coordinación e integración | Organizar tareas, revisar solicitudes y vigilar que `main` funcione |
| 2 | Acceso y perfiles en frontend | Registro, inicio de sesión y perfil público |
| 3 | Artículos en frontend | Listado, buscador, filtros, detalle y formulario de artículo |
| 4 | Usuarios y acceso en backend | API de registro, sesión, permisos y perfiles |
| 5 | Artículos y mensajes en backend | API de artículos, imágenes, búsqueda y conversaciones |
| 6 | Datos, moderación y calidad | Migraciones, reportes, panel de moderación y pruebas |

## Orden recomendado

### Primera etapa

- Acordar nombre y estilo visual.
- Preparar registro e inicio de sesión.
- Crear usuarios, roles y categorías en la API.
- Definir cómo se guardarán las imágenes.

### Segunda etapa

- Crear, editar y listar artículos.
- Añadir búsqueda y filtros.
- Aplicar permisos para que solo el propietario pueda editar.

### Tercera etapa

- Crear mensajería por artículo.
- Crear reportes y flujo de moderación.
- Crear panel de administración.

### Cuarta etapa

- Completar pruebas.
- Corregir errores.
- Preparar datos de demostración y documentación de entrega.
- Añadir funciones opcionales solo si lo obligatorio está terminado.

## Acuerdos que faltan

- Nombre de la plataforma.
- Logotipo y colores.
- Nombres y usuarios de GitHub de las seis personas.
- Responsable de cada bloque.
- Día y hora de la reunión semanal.
- Dónde se guardarán las imágenes en producción.
